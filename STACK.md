# Stack

## Decision

- **Engine: C (C11) + SDL3 + libopenmpt**, statically linked into a single `AlfabetSmierci.exe`.
- **Tooling: Python** (decruncher, extractors, asm lifter), unchanged from phases 1-2.
- **Game logic: data, not code.** The lifter writes one readable script file per location. The engine loads these scripts, so the logic is not tied to C, or to any other language.

## Why this and not something else

**Faithful music, the top priority.** The game's music is two *The Player 6.0A* modules by Michał 'Dixan05' Prochownik. The extractor converts them to ProTracker MOD symbolically: every note, effect and original 8-bit sample byte is kept. Nothing is pre-rendered and nothing is lossy. At runtime, libopenmpt synthesises the sound live with its Amiga resampler emulation (BLEP-based Paula output). That emulation has a selectable **A1200** filter model, which is the machine this game targets. libxmp can read P60A directly, but it only models the A500, so it is the weaker choice for this game.

**Small and portable.** The exe is 8.9 MB (most of it libopenmpt with all its format loaders), plus 3.5 MB of original disk images, with no installer, no runtime, no admin rights and nothing written outside the folder. A Python + pygame build (PyInstaller) would land at 30-60 MB, start slower and trip antivirus heuristics more often. Its mixer also can't emulate Paula, so it would end up calling libopenmpt anyway.

**Pixel exact by construction.** The engine keeps the same model as the Amiga: a 640x256 8-bit indexed framebuffer plus a 256-entry palette, with colours 0-127 for the scene and 128-255 for the UI. Palette fades work on indices exactly like the original copper code. Each frame is converted to RGBA once and shown with integer nearest-neighbour scaling. No filtering is ever applied.

**Readable for Maniak.** Plain C in small modules is the closest thing to the original asm. All of the interesting game logic lives in the location scripts anyway.

Alternatives considered:

| Option | Verdict |
|---|---|
| Python + pygame-ce | Fastest to prototype. Loses on size, startup and audio (no Paula emulation without libopenmpt). |
| Rust + SDL | Very good, but the toolchain is heavier and the code would be less familiar to the original author. No real gain over C here. |
| C++ | libopenmpt itself is C++ (with a C API), so the toolchain needs a C++ compiler anyway. The engine stays plain C for simplicity. |
| libxmp instead of libopenmpt | Smaller and pure C, reads P60A natively, but only models the A500 filter. Kept as a fallback. |

## Screen

- The native frame is 640x256 hires. It is displayed as **640x512** (each line doubled, as the Amiga's hires pixels are about twice as tall as they are wide). It is then scaled by the largest **integer** factor that fits the screen. That gives x2 = 1280x1024 on 1080p and 1440p, and x4 = 2560x2048 on 4K. There is no stretching, no filtering and no widescreen fill of the game image.
- Exact PAL hires aspect would need a further 1.067x horizontal stretch, which is not an integer, so it is deliberately left out.
- In widescreen, the space left and right of the image gets the side panels (options on the left, decoration on the right). They are drawn in the same Amiga pixel grid (hires columns, doubled lines) with the game's own font and textures, so they scale with the game and never look sharper than it.

## Timing

The original runs off the 50 Hz PAL vertical blank. The engine runs its logic at a fixed 50 Hz tick and renders at the display's refresh rate. Music runs on the audio thread at 48 kHz. Its tempo comes from the module (CIA/VBL speed), as on the Amiga.

## Toolchain (needs your OK, see question below)

The PC has no C compiler at the moment. Proposal:

- **w64devkit** (portable MinGW-w64 GCC 14 for Windows, by Christopher Wellons). It is a ~90 MB zip unpacked into `tools/`, with no installer and no admin rights.
- **CMake portable** (~50 MB zip) to build SDL3 and libopenmpt as static libraries.

Alternative: **Zig** (~80 MB, single folder), used as a C/C++ compiler (`zig cc`). It is equally portable and also cross-compiles, but it is less common for building SDL and libopenmpt.

MSVC Build Tools are not proposed: they need several GB and an admin install.
